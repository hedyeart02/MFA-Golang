# SAMLGuard Security Guide

## Overview

SAMLGuard implements defense-in-depth security across all microservices. This guide covers the security architecture, threat mitigations, and operational security practices.

## SAML Security

### XML Signature Validation
- All SAML assertions MUST be signed
- Unsigned assertions are rejected
- XML signatures are verified against trusted IdP certificates
- The signing certificate must match a pre-configured trusted certificate

### Replay Attack Prevention
- Every assertion ID is tracked in a replay cache
- Duplicate assertion IDs are rejected
- Cache entries expire after the assertion's NotOnOrAfter timestamp
- Cache cleanup runs every 5 minutes

### Timestamp Validation
- NotBefore and NotOnOrAfter conditions are enforced
- Maximum clock skew of 30 seconds (configurable)
- Expired assertions are rejected

### Issuer & Audience Validation
- Issuer must match the configured trusted IdP entity ID
- Audience restriction must include the gateway's entity ID
- Unknown issuers are rejected

## MFA Security

### TOTP Secrets
- Encrypted at rest using AES-256-GCM
- Encryption key is 256-bit, loaded from environment variable
- Never stored in plain text
- Never logged

### OTP Codes
- 6-digit numeric codes (configurable up to 10)
- 5-minute expiration (configurable)
- Maximum 5 retry attempts per window
- 15-minute rate limit window after max retries
- Codes are never logged

### Backup Codes
- Generated using cryptographic random number generator
- Stored as bcrypt hashes (cost factor 12)
- Single-use — consumed on validation
- 10 codes generated by default

## Session Security

### JWT Tokens
- RS256 (asymmetric) signing
- Short-lived access tokens (15 minutes)
- Longer refresh tokens (24 hours)
- Issuer and subject claims validated
- Token hash stored in session record (not the token itself)

### Session Management
- Idle timeout: 30 minutes
- Absolute timeout: 12 hours
- Session revocation support
- Bulk session revocation per user

### Cookies
- `Secure` flag: enabled (HTTPS only)
- `HttpOnly` flag: enabled (no JavaScript access)
- `SameSite`: Strict (CSRF protection)
- Session cookie, not persistent

## Transport Security

### TLS
- TLS 1.2+ enforced at Nginx
- Strong cipher suites only
- HSTS header with 1-year max-age, includeSubDomains, preload
- HTTP automatically redirected to HTTPS

### Inter-Service Communication
- API key authentication (Bearer token)
- Correlation ID propagation for tracing
- Configurable request timeouts
- Internal services not exposed through Nginx

## HTTP Security Headers

All responses include:
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `X-XSS-Protection: 1; mode=block`
- `Strict-Transport-Security: max-age=31536000; includeSubDomains; preload`
- `Content-Security-Policy: default-src 'self'`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Permissions-Policy: camera=(), microphone=(), geolocation=()`
- `Cache-Control: no-store, no-cache, must-revalidate`

## Logging Security

### What is logged
- Request method, path, status, latency
- Client IP and user agent
- Correlation and request IDs
- Event types and actions (audit)
- Error messages (sanitized)

### What is NEVER logged
- Passwords
- OTP codes
- SAML assertion contents
- JWT tokens
- Encryption keys
- Session tokens
- MFA secrets

## Error Handling

- Stack traces are never exposed to clients
- Panics are caught by recovery middleware
- Consistent error response format
- Internal errors return generic messages
- Detailed errors logged server-side only

## Rate Limiting

### Nginx Layer
- General endpoints: 100 requests/second
- Authentication endpoints: 10 requests/second
- MFA verification: 5 requests/second

### Application Layer
- MFA: 5 attempts per 15-minute window
- Per-user rate limiting via retry counters

## Recommendations for Production

1. **Replace self-signed certificates** with CA-signed certificates
2. **Set strong API keys** via environment variables, not config files
3. **Generate a unique MFA encryption key** and store securely
4. **Enable database encryption** for SQLite (e.g., SQLCipher)
5. **Implement mTLS** for inter-service communication
6. **Deploy behind a WAF** (Web Application Firewall)
7. **Enable audit log forwarding** to SIEM system
8. **Regularly rotate** SAML signing certificates
9. **Monitor** for replay attacks and excessive MFA failures
10. **Implement CSRF tokens** with server-side validation
