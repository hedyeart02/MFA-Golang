Cross-Platform Deployment & config.yaml Setup

Step-by-step instructions to upload SAMLGuard release packages, configure config.yaml, install certificates, and manage the service across Webmin, Linux (systemd), and Windows Server.

Webmin (:10000) Linux (Ubuntu / Debian / RHEL) Windows Server config.yaml Reference

1. Webmin (Linux Appliance / Server Management)

Port :10000 + systemd

SAMLGuard includes a native Webmin module package (dist/samlguard-webmin.wbm.gz) that adds a SAMLGuard section to the Webmin sidebar with five modules: About, Certificates, Debug, Setup, and Status.

Step 1: Upload & Install the Webmin Module

  1. Install the standalone Linux service first (see Section 2) so /etc/samlguard/config.yaml and samlguard.service exist.
  2. Log in to Webmin at https://<server-ip>:10000.
  3. Navigate to Webmin → Webmin Configuration → Webmin Modules.
  4. Select From uploaded file, choose dist/samlguard-webmin.wbm.gz, and click Install Module.
  5. Click Refresh Modules in the bottom-left Webmin sidebar to reveal the SAMLGuard menu.

Step 2: Configure config.yaml & Certificates in Webmin

  1. Open SAMLGuard → Setup to view the gateway summary and edit /etc/samlguard/config.yaml directly from your browser, then save.
  2. Open SAMLGuard → Certificates to inspect X.509 certificates or upload .crt / .key files directly into /etc/samlguard/cert/.
  3. Open SAMLGuard → Status to Start, Stop, Restart, or Enable samlguard.service at boot and verify the health probe.
  4. Open SAMLGuard → Debug to filter or download live journalctl -u samlguard logs.

One-Click Application Upgrade via Webmin

In SAMLGuard → Status → Upgrade SAMLGuard Application, upload samlguard-vX.Y.Z-linux-amd64.tar.gz (or arm64). Webmin automatically verifies the binary, backs up /usr/local/bin/samlguard and samlguard.db, swaps the binary, reapplies cap_net_bind_service, restarts the service, and rolls back if startup fails.

2. Linux (Ubuntu, Debian, RHEL, Rocky, AlmaLinux, CentOS)

systemd + Pure-Go Binary

Step 1: Upload & Extract Package

Upload the archive for your architecture (linux-amd64 or linux-arm64) to the Linux host and extract it:

scp dist/samlguard-v1.1.1-linux-amd64.tar.gz root@<server-ip>:/tmp/
ssh root@<server-ip>
mkdir -p /tmp/samlguard-pkg && tar -xzf /tmp/samlguard-v1.1.1-linux-amd64.tar.gz -C /tmp/samlguard-pkg
cd /tmp/samlguard-pkg/*

Step 2: Run Installer & Upload Certificates

Run the installer script (creates user samlguard, /etc/samlguard/config.yaml, and grants port 80/443 capability):

sudo ./scripts/linux/install.sh ./samlguard
# Upload or copy your TLS/SAML certs if using static certs:
sudo cp server.crt server.key saml-signing.crt saml-signing.key /etc/samlguard/cert/
sudo chown -R samlguard:samlguard /etc/samlguard/cert
sudo chmod 600 /etc/samlguard/cert/*.key

Step 3: Edit /etc/samlguard/config.yaml & Start Service

sudo nano /etc/samlguard/config.yaml
sudo systemctl daemon-reload
sudo systemctl enable --now samlguard
sudo systemctl status samlguard
sudo journalctl -u samlguard -f

Step 4: Firewall & Future Upgrades

# Ubuntu / Debian (UFW):
sudo ufw allow 8443/tcp   # or 80,443/tcp for Let's Encrypt

# RHEL / Rocky / AlmaLinux (firewalld):
sudo firewall-cmd --permanent --add-port=8443/tcp
sudo firewall-cmd --reload

# Upgrade later:
sudo bash scripts/linux/upgrade.sh /tmp/samlguard-v1.1.1-linux-amd64.tar.gz

3. Windows Server (Windows Service / SCM)

Windows Server 2019 / 2022 / 11

Step 1: Upload & Install Windows Service

  1. Copy dist\samlguard-v1.1.1-windows-amd64.zip to the Windows server and extract it (e.g. C:\Temp\samlguard).
  2. Open PowerShell as Administrator inside the extracted folder and run:
.\scripts\windows\install-service.ps1 -BinarySource .\samlguard.exe

Installs binary to C:\Program Files\SAMLGuard\samlguard.exe and data/config to C:\ProgramData\SAMLGuard\.

Step 2: Configure config.yaml, Certs & Firewall

  1. Edit C:\ProgramData\SAMLGuard\config.yaml (Notepad / VS Code as Administrator).
  2. Place certificates in C:\ProgramData\SAMLGuard\cert\ (if not using Let's Encrypt).
  3. Open the firewall port and manage the service in elevated PowerShell:
New-NetFirewallRule -DisplayName "SAMLGuard" -Direction Inbound -Protocol TCP -LocalPort 8443 -Action Allow
Start-Service SAMLGuard
Get-Service SAMLGuard

Upgrading on Windows Server

Stop-Service SAMLGuard
Copy-Item .\samlguard.exe "C:\Program Files\SAMLGuard\samlguard.exe" -Force
Start-Service SAMLGuard

4. config.yaml Reference & Cloud Let's Encrypt Example

System Settings →

Path locations: /etc/samlguard/config.yaml (Linux/Webmin) or C:\ProgramData\SAMLGuard\config.yaml (Windows). 

server:
  host: "0.0.0.0"
  port: 443                       # Use 443 for cloud/Let's Encrypt, or 8443/18080 if co-hosted

tls:
  enabled: true
  # Option A: Static certificates (on-prem / internal CA)
  cert_file: "/etc/samlguard/cert/server.crt"
  key_file: "/etc/samlguard/cert/server.key"
  # Option B: Automatic Let's Encrypt SSL (cloud / public DNS domain with ports 80 & 443 open)
  auto_tls:
    enabled: false
    domains:
      - "sso.yourdomain.com"
    email: "admin@yourdomain.com"
    cache_dir: "certs/autocert"
    http_challenge_addr: ":80"

database:
  driver: "sqlite"
  path: "/var/lib/samlguard/samlguard.db"  # Windows: C:\ProgramData\SAMLGuard\data\samlguard.db

saml:
  entity_id: "https://sso.yourdomain.com"
  sso_url: "https://sso.yourdomain.com/saml/sso"
  slo_url: "https://sso.yourdomain.com/saml/slo"
  acs_url: "https://ita.example.com/api/current/authentication/saml2-callback"
  cert_file: "/etc/samlguard/cert/saml-signing.crt"
  key_file: "/etc/samlguard/cert/saml-signing.key"
  customer_tenants:
    - id: "acme-corp"
      name: "Acme Corp Enterprise"
      sp_entity_id: "https://acme.example.com/saml/metadata"
      acs_url: "https://acme.example.com/api/current/authentication/saml2-callback"
      enabled: true
