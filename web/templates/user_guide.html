1. Overview & SAML 2.0 Proxy Architecture

Core Flow

{{if .Branding.AppName}}{{.Branding.AppName}}{{else}}SAMLGuard{{end}} operates as a SAML 2.0 Identity Provider Proxy between your downstream enterprise Service Providers (such as {{if .Branding.TargetAppName}}{{.Branding.TargetAppName}}{{else}}Schneider Electric IT Advisor{{end}} or any SAML 2.0 application) and upstream corporate IdPs (Microsoft Entra ID, Keycloak, Okta, ADFS, or the built-in Simulator).

1. User opens Downstream SAML App  ──► App redirects browser with SAML AuthnRequest to /saml/sso
2. Gateway validates request       ──► Checks binding, XML schema, signature, replay protection, allowed audience
3. Upstream Corporate IdP sign-in  ──► User authenticates at Entra ID / Keycloak / Custom IdP (returns to /saml/acs)
4. User Access & MFA Challenge     ──► Gateway verifies allowlist (if enforced) + prompts TOTP / Email OTP / SMS OTP
5. Signed Downstream Assertion     ──► Gateway maps roles/groups and issues signed SAML Response to Downstream ACS URL

2. Quick Start Setup Checklist

Open Identity Providers →
  1. Sign in & rotate default password: Log into /admin/login (initial default credentials admin / admin) and complete the mandatory password update at /admin/change-password.
  2. Exchange SAML Metadata: Download SP Metadata XML from System Settings to upload to your upstream IdP (Entra ID / Keycloak), and download IdP Metadata XML (or public .crt) to configure your downstream application.
  3. Select Upstream IdP(s): In the Identity Providers tab, choose Simulator, Microsoft Entra ID, Keycloak, or Custom SAML 2.0, enter Entity ID / SSO URL / X.509 Certificate, and enable one or multiple providers.
  4. Enable MFA Methods: Turn on Authenticator App (TOTP), Email OTP (with SMTP settings & Test Email), and/or SMS OTP (with gateway credentials & Test SMS).
  5. Configure Downstream Application & Branding: Set Downstream SP Entity ID, ACS URL, Group Mappings in Service Providers, and optionally tailor app name, logos, and backgrounds in System Settings → Custom Theme & Branding Profiles.
  6. Save Configuration: Click Save Configuration on the bottom action bar. Changes persist immediately in the SQLite gateway_settings table across restarts.

3. Configuring Upstream Identity Providers

Manage Upstream IdPs →

Each IdP card stores an isolated configuration profile so you can configure multiple IdPs simultaneously without losing credentials when switching.

Supported Upstream IdPs

  • Simulator (Mock IdP): Built-in test login screen at /mock-idp/submit for safe offline testing without an external IdP. (Disallowed in production mode.)
  • Microsoft Entra ID: Configure Tenant Login URL (SSO URL), Azure AD Identifier (Entity ID), and Federation Metadata XML URL or downloaded PEM certificate.
  • Keycloak: Use realm SAML endpoint (.../realms/<realm>/protocol/saml) and realm descriptor URL.
  • Custom SAML 2.0: Connects to Okta, ADFS, Ping Identity, Auth0, or any standard SAML 2.0 Identity Provider.

Multi-Provider Login Experience

  • Single Active IdP: Users signing in at /saml/sso can either auto-continue or sign in via your primary active IdP.
  • Multiple Enabled IdPs: Checking multiple IdPs presents a clean provider selection screen on the corporate login page so users pick their organization directory.
  • SAML Request Binding: Share this gateway's SP Entity ID ({{.Settings.EntityID}}) and ACS URL ({{.Settings.ACSURL}}) with your upstream IdP.

4. Multi-Factor Authentication (TOTP, Email & SMS OTP)

Configure MFA & SMTP →

Authenticator App (TOTP)

Users scan a QR code on first sign-in using Microsoft Authenticator, Google Authenticator, or any RFC 6238 app. Secrets are encrypted at rest with AES-256-GCM. Admins can trigger a fresh QR re-enrollment per user under User Groups → Reset MFA.

Email OTP (SMTP)

Sends time-limited HMAC-SHA256 verification codes over SMTP (STARTTLS or SMTPS). Use the built-in Send Test Email diagnostics button after entering SMTP Host, Port, Sender Address, Username, and Password.

SMS OTP (Cloud & Hardware)

Supports Twilio, iSMS, Vonage, SendQuick, SMSEagle, MultiTech iSMS, Teltonika RUT/TRB, and Custom HTTP/JSON gateways. Store mobile numbers in E.164 format (e.g. +60123456789) and validate using Send Test SMS.

Default Verification Policy: Choose Let User Choose (select) when multiple MFA methods are enabled to let users switch between Authenticator App, Email OTP, and SMS OTP at login, or pin a mandatory default method.

5. Service Providers, Audiences & Group Mapping

Open Service Providers →

Downstream SAML App Integration

  • Import SAMLGuard's IdP Metadata from /saml/metadata/idp (or /metadata) into your target application.
  • Add every downstream application's SP Entity ID to Allowed Audiences (comma-separated) so SAMLGuard accepts its AuthnRequests.
  • Verify Downstream ACS URLs include the target app's SAML callback URL.

Role & Group Translation

  • Use Group Mapping to translate upstream directory group IDs/names (e.g. Entra Object ID or cn=ITA-Admins) into downstream role names expected by your target app.
  • Assign fallback roles in Default Groups when an upstream assertion carries no mapped group claims.

6. User Whitelist & Access Control

Manage Users →
  • Enforce User Whitelist: When enabled, only users present in the gateway database (via manual entry or API sync) are permitted to complete SSO sign-in.
  • Add & Edit Users: Manually whitelist users with Username, Email, Full Name, and E.164 Phone Number (required for SMS OTP delivery when the upstream IdP does not provide a phone claim).
  • EcoStruxure™ IT Advisor Sync: Configure ITA API URL & credentials to pull authorized ITA users directly via Sync Users Now.
  • Reset TOTP Enrollment: Use Reset MFA if a user replaces their phone so they are prompted to scan a new authenticator QR code on next sign-in.

7. Custom Theme & Branding Profiles

Customize Theme Profiles →

Located in System Settings, theme profiles make integrating additional downstream SAML applications fast by letting you save reusable brand presets (default EcoStruxure™ profile or custom app profiles) applied across Corporate Sign-In, MFA Verification, Error Pages, Admin Login, and the Admin Console.

App Naming, Colors & Toggles

  • Profile Display Name: Selector card label in System Settings.
  • Portal / App Name & Target App Name: Replaces SAMLGuard and Schneider Electric IT Advisor in page titles, headings, sign-in prompts, sidebar, and footer.
  • Primary Accent Color: Hex picker/input updates buttons, focus rings, sidebar highlights, and shield glow.
  • Visibility Toggles: Show or hide App Card Icon, Header Left Logo, Header Subtitle, and Organization/Corner Logo (1-click Generic App Template sets clean app-agnostic defaults).

Uploading Custom Media Assets

  • Upload images up to 5 MB directly in PNG, JPG/JPEG, WebP, GIF, ICO, or safe sanitized SVG format — stored durably in SQLite (branding_assets) and served from /branding/assets/:id.
  • Independent upload slots exist for App Card Icon, Browser Favicon, Header Logo (Dark & Light), Organization Logo, Login/MFA Backgrounds (Dark & Light), and Admin Console Backgrounds (Dark & Light).
  • Click Reset on any slot (or Reset Profile) to revert immediately, then click Save Configuration.

9. Troubleshooting & FAQ

Diagnostics

SAML Assertion or Audience Errors

  • Verify system clocks on Gateway, Upstream IdP, and Downstream App are synchronized via NTP.
  • Confirm the Downstream App's Entity ID is listed in Allowed Audiences in Service Providers.
  • Check that the Upstream IdP certificate matches the signing key currently used by Entra/Keycloak.

OTP Delivery & Theme Display Issues

  • Email/SMS fails: Run Send Test Email or Send Test SMS in Identity Providers and ensure the user record includes a valid email / E.164 phone number.
  • User lost Authenticator phone: Click Reset MFA next to the user in User Groups so they can enroll a new device.
  • Theme not updating: Make sure you clicked Save Configuration at the bottom of System Settings and clear browser cache if testing an updated favicon.
